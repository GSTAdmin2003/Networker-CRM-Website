How should the leads page fetch and update data?

Three approaches — pick based on how much you care about real-time updates.

A

Server-rendered table + client interaction (recommended)

Page server component fetches all leads on load and passes them to a client component. Client handles filtering, checkbox selection, CSV generation, and calls PATCH /api/leads to mark downloaded. No GET API endpoint needed — data comes from the server render.

Pros

  • Instant first paint — data already there
  • Simpler — fewer moving parts
  • Consistent with existing page pattern

Cons

  • Stale after download — requires page refresh to see updated badges
B

Client fetches from API

Client component calls GET /api/leads on mount, then PATCH /api/leads on download. Can re-fetch after marking downloaded so badges update live.

Pros

  • Can refresh data after marking downloaded

Cons

  • Loading spinner on page open
  • Extra API endpoint to build and secure
C

Server-rendered + optimistic update

Same as A but the client optimistically flips downloaded badges locally after the PATCH succeeds — no page refresh needed, no extra GET endpoint.

Pros

  • Instant feedback
  • No GET endpoint needed

Cons

  • Slightly more client logic
