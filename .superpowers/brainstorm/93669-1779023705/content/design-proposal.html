Design: JS-Enforced 6·3·1 Ratio

A ResizeObserver hook measures section heights, solves for the exact padding needed to hit 30% navy, and applies it live via a CSS custom property — no flash, no infinite loop.

The math (runs on every resize)

// Read current state L = Σ offsetHeight of dominant sections D_cur = Σ offsetHeight of secondary sections extra = CSS var(--ratio-padding-extra) currently applied // from getComputedStyle N = 2 // Problem + Waitlist D_min = D_cur − N × 2 × extra // dark content without extra padding // Solve for extra padding that hits 30% // dark / total = 0.30 → solve for extra: new_extra = (0.30 × L − 0.70 × D_min) / (0.70 × N × 2) new_extra = clamp(new_extra, 0, 120) // px per side, min 0, max 120 // Apply only if meaningfully different (prevents oscillation) if |new_extra − extra| > 0.5px → set --ratio-padding-extra

What gets built

New hook

hooks/useColorRatio.ts

ResizeObserver watching all [data-color-role] elements. Runs the math, sets the CSS var. Cleans up on unmount.

CSS change

.problem, .waitlist padding becomes:

calc(var(--ratio-padding-base, 64px) + var(--ratio-padding-extra, 32px)) 0

Base = minimum comfortable padding. Extra = JS-controlled.

Markup change

Add data-color-role to section roots in Problem.tsx, Waitlist.tsx, and all dominant sections. One attribute per component.

Wired in

LandingPage.tsx calls useColorRatio(). Already a client component. No new client boundaries needed.

Constraints & guardrails

  • Extra padding is clamped to 0–120px per side — dark sections never collapse or become excessively tall
  • If dark sections can't reach 30% (content too short), the hook does nothing rather than over-padding
  • Threshold of 0.5px before re-applying prevents ResizeObserver feedback loops
  • Hook runs on mount + every resize — no polling, no intervals
  • Teal (10%) is not adjusted — it's used for text/icons, not background area
