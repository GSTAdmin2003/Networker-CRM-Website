How should the two phases submit?

Phase 1 saves the phone. Phase 2 adds details to the same row. The question is how they're linked.

A

Two endpoints — recommended

Phase 1 POST /api/contact → saves phone, returns row id. Phase 2 PATCH /api/contact → sends that id + details, updates the same row. ID is held in React state only — never in the URL.

Pros

  • Phone saved the instant they hit submit
  • Phase 2 enriches the same row cleanly
  • Simple to implement

Cons

  • Row ID sent to client (UUIDs, low risk)
B

Single endpoint, phase flag

POST /api/contact with phase: 1 → saves phone. Same endpoint with phase: 2, id → updates. Functionally identical to A but one route file instead of two.

Pros

  • One route file to maintain

Cons

  • Slightly messier handler logic
